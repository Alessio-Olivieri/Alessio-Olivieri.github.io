Useful again, through an open Android client

The Gear S3 still has capable hardware, but its companion software ties everyday use to a vendor ecosystem. I developed an Android-side integration in an independent Gadgetbridge fork to recover practical features on the watch.

My contribution

I implemented and debugged device communication and connection management, notification delivery, interactive notification actions and replies, and contact synchronization. The work crosses the Android notification lifecycle and the watch’s Bluetooth/SAP protocol behavior.

  • Stable reconnects: investigated lifecycle failures when a connection drops and is re-established.
  • Working actions: corrected notification action IDs and reply handling so that a visible notification can also be acted on.
  • Contact synchronization: resolved synchronization behavior and duplicate-contact issues.

How I checked it

Exercised the integration with physical devices and added regression checks around protocol and notification behavior. This matters because a successful connection is only the first step: replies, reconnects and state synchronization need to keep working after that.

Current scope. This is experimental, independent development on top of Gadgetbridge. It has not been merged upstream, and support across firmware versions and all watch features is not established. Initial setup can still depend on Samsung’s pairing flow.

Code and attribution

The original Gadgetbridge project provides the base application. My fork publishes the Gear S3 work separately and preserves upstream attribution and licensing.
